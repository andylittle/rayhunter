# Alcatel LinkZone MW41MP

The Alcatel LinkZone MW41MP (MetroPCS SKU, built by TCL) is a Qualcomm
MDM9207-based mobile hotspot available used for roughly $10-20. It has no
screen. It does have status LEDs, but the stock firmware actively repaints
all of them (signal, battery, SMS, WiFi) every second or so to reflect real
device status, reverting any value Rayhunter writes within a few seconds.
Rayhunter currently runs headless on this device (no LED indicator) as a
result; this may be revisited if a way to disable that behavior turns up.

## Supported bands

Refer to the device's FCC ID for the exact band list for your unit.

## Hardware

- SoC: Qualcomm MDM9207 (Cortex-A7, armv7)
- 256 MB NAND, split into a small root filesystem and a `/cache` partition
- microSD slot (varies by unit; not present on all SKUs)
- No display; status LEDs only

## Installing

The MW41MP enumerates over USB as a mass-storage device. A documented
vendor SCSI command (public since 2021, used by TCL's own factory service
tool) switches it into a debug mode that starts `adbd` as root; this is not
an exploit, just an undocumented-but-public factory feature. With the
device connected via USB and fully booted (WiFi network visible), run:

```sh
./installer mw41
```

This requires root/administrator privileges on your computer, since sending
the raw USB command needs elevated access to the device (on Linux, run the
installer with `sudo`). **Currently only supported on Linux** -- on other
platforms, switch the device into debug mode manually (see "Obtaining a
shell" below) and the rest of the install should still work once `adb
devices` shows it.

Rayhunter needs a microSD card to store recordings on this device (its
internal storage has only a few tens of MB free). The installer checks for
one and stops with instructions if it can't find one; pass `--skip-sdcard`
to install anyway and store recordings in that limited internal space (not
recommended -- expect only a few hours of recording before it fills up).

If you have the Android `adb` tool installed and its server is running, it
will hold the device's ADB interface and the installer can't connect. Run
`adb kill-server` first.

## Obtaining a shell

```sh
sudo ./installer util mw41-shell
```

Debug mode does not persist across a reboot; this switches the device back
into it each time. Plain `adb shell` also works once the device is in debug
mode (`sudo ./installer util mw41-start-adb` switches it without opening a
shell).

## LED modes

Not currently supported; see the note above. Check the web UI (port 8080)
for recording status instead.

## Developing

`/dev/diag` on this device is already shared concurrently by several stock
processes, so no vendor daemon needs to be stopped to use it. It does need
the same alternate `DIAG_IOCTL_SWITCH_LOGGING` parameters some TP-Link
M7350 revisions need -- the default parameters fail outright on this SoC.

Files are installed to `/cache/rayhunter/` rather than `/data/rayhunter/`:
this device's root filesystem (where `/data` lives) has almost no free
space. Unlike other non-`/data` devices, a `/data/rayhunter` symlink
doesn't work here either -- `/data` resets to empty on every boot -- so the
init script's paths are patched directly instead.
